TRANSACTION LOGIC

A clear state machine for every purchase.

04

SECURITY BOUNDARIES

Minimize sensitive data by design.

Never collect wallet secrets

Seed phrases, private keys, recovery phrases, and raw banking credentials are rejected.

Tokenized payment references

The prototype models provider tokens and transaction IDs instead of storing card data.

Least-privilege access

Buyer, seller, merchant, reviewer, and administrator capabilities are separated.

Immutable audit events

Each material state change creates a timestamped event for later review.

Human escalation

Automation can organize evidence, but ambiguous or high-risk decisions require review.

Prototype-safe operation

This release simulates funds and is not a licensed custody, escrow, or banking service.

DISPUTE ENGINE

Automate collection, not blind judgment.

v3.003 classifies disputes, pauses release, requests evidence, checks deadlines, and recommends an outcome. Human review remains mandatory for uncertain cases.
